# Assignment 3: Benchmarking Approximate Nearest Neighbour Search

CS4.406 Information Retrieval & Extraction · roll number 2024101103.

## Setup

Python 3.11 with:

```bash
pip install -r requirements.txt
```

Put the two ann-benchmarks files in `data/`. They are not in the repo:

```
data/sift-128-euclidean.hdf5
data/glove-100-angular.hdf5
```

Set `ANN_DATA_DIR` to use a different folder. Exact ground truth is computed once
with FAISS and cached in `data/cache/`. Part 4's data is generated by the code
(seeded), so it needs no files.

## Running

```bash
bash run_all.sh          # everything, all base vectors          -> results/        (~2 h on the test laptop)
bash run_all.sh --quick  # same pipeline, first 100,000 vectors  -> results_quick/  (under 15 min)
```

`run_all.sh` runs, in order:

1. the unit tests for recall@10
2. a record of the machine and library versions (`results/environment.json`)
3. Parts 1 to 4
4. a check of timing bias right after a build
5. the relative contrast of SIFT and GloVe
6. a merge of every run into `results/results.csv`

Together these regenerate every number, table and figure in the report from the
data files. `--quick` uses the first 100,000 base vectors of SIFT and GloVe and
50,000 vectors per Part 4 setting. It times fewer queries (300), pauses 2 s
instead of 20 s after each build, and trains PQ codebooks on 25,000 vectors.
Its numbers are smaller and noisier, but every output file is produced.

For timing, run on mains power with the laptop awake. The scripts ask Windows not
to sleep, and every timed row records `ac_power`.

The report PDF is built from `report/report.html`, which uses the figures in
`results/figures/`:

```bash
bash report/build_pdf.sh    # needs Chrome or Edge
```

## Conventions

- GloVe vectors and queries are L2-normalised; Euclidean distance is used everywhere.
- Queries 0-4,999 are used for tuning and 5,000-9,999 for reported numbers.
- Recall@10: a returned id counts as correct if its exact distance is no larger
  than the true 10th-neighbour distance, so ties at the 10th neighbour are not mistakes.
- Speed: queries per second, one query per call, one thread, median of 5 timed passes.
  Parts 2-4 time the first 2,000 test queries. Exact one-query-at-a-time timing uses
  the first 500 (Part 1) or 300 (Part 4), since it takes ~30 ms per query at 1M.
  Index building uses all cores. Timing starts 20 s after each build, because
  measuring straight after an all-core build was slow on this laptop
  (`check_timing_bias.py`).
- Operating points (e.g. "QPS at recall 0.95") are chosen on the tune queries only:
  the setting with tune recall >= target and the highest QPS on tune queries. Its
  recall and QPS are then measured on the test queries.
- Outputs: `results/raw/*.csv` (every run), `results/results.csv` (all runs merged),
  `results/tables/`, `results/figures/`.
